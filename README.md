# Flag Icons · Flag Icon Resources

A pure **SVG** flag icon resource library, with an `index.html` preview / documentation site, plus an edge function `region-name` for resolving a code to a region name. The resources follow the `flag-icons` directory convention: SVG only, two aspect ratios only.

## Resources

- **Single format**: SVG only — vector, scales to any size without quality loss. No PNG / WebP / multiple size tiers.
- **Two aspect ratios**: file names are identical and one-to-one matched, 271 each, 542 files total:

  | Directory | Ratio | viewBox | Typical use |
  |-----------|-------|---------|-------------|
  | `4x3/` | 4:3 | `0 0 640 480` | Standard rectangular national flags |
  | `1x1/` | 1:1 | `0 0 512 512` | Avatars / circular / square containers |

- **Naming rule**: `<ratio dir>/<code>.svg`, codes are always lowercase.
  - Countries: `cn`, `us`, `jp`, `br` … (ISO 3166-1 **alpha-2**)
  - Sub-regions: `gb-eng` (England), `gb-sct`, `es-ct` (Catalonia), `es-ga`, `es-pv`, `sh-ac`, `sh-hl`, `sh-ta` … (hyphenated)
  - Organizations / supplementary codes: `eu`, `un`, `arab`, `asean`, `cefta`, `eac`, `pc`, `ic`, `cp`, `dg`, `xx` and 17 non-ISO supplementary codes in total

- **One-China principle**: `tw → Taiwan, China`, `hk → Hong Kong, China`, `mo → Macao, China`, fixed via the `OVERRIDE` table in both `flag.js` and `region-name.js`.

## Quick Start

The deployable site lives in the `dist/` directory. To build and preview locally:

```bash
# 1) (Re)generate dist/flags.css — resource domain is REQUIRED (one of the two)
node build.mjs https://your.cdn/               # option A: pass domain as CLI argument
FLAG_DOMAIN=https://your.cdn/ node build.mjs   # option B: pass domain via FLAG_DOMAIN env var
# If no domain is provided it errors out immediately (exit 1) — no file is generated.

# 2) Preview
cd dist && python -m http.server 8000
# open http://127.0.0.1:8000
```

> `flags.css` is generated by `build.mjs` and is git-ignored (see `.gitignore`); it is not part of the committed source.

Path rule: `<ratio dir>/<code>.svg`.

Common conventions: pick the ratio first, then size; always declare `width/height` explicitly or use `aspect-ratio`; always write `alt` (empty string for decorative use, the country/region name when meaningful).

```html
<!-- ① 4:3 rectangle: default usage -->
<img src="4x3/cn.svg" width="48" height="36" alt="China">

<!-- ② 1:1 square: avatar / circular container -->
<img src="1x1/cn.svg" width="48" height="48" alt="China">

<!-- ③ Inline icon: width/height scaled to 4:3 -->
<img src="4x3/us.svg" width="20" height="15" alt="United States" loading="lazy">

<!-- ④ The same SVG can be scaled up to any size -->
<img src="4x3/cn.svg" width="320" height="240" alt="China">
```

```css
.flag-4x3 {                 /* 4:3 background image */
  width: 48px;
  aspect-ratio: 4 / 3;      /* lock ratio, avoid layout shift */
  background: url("4x3/cn.svg") center / contain no-repeat;
}
.flag-1x1 {                 /* 1:1 round avatar */
  width: 48px;
  aspect-ratio: 1 / 1;      /* lock ratio, avoid layout shift */
  background: url("1x1/cn.svg") center / cover no-repeat;
  border-radius: 50%;
}
```

```jsx
// React — just pass ratio to switch between square / rectangle
const H = { "4x3": 0.75, "1x1": 1 };
const Flag = ({ code = "cn", ratio = "4x3", size = 48, alt = "" }) => (
  <img src={`${ratio}/${code}.svg`}
       width={size} height={Math.round(size * H[ratio])}
       alt={alt || code} loading="lazy" />
);
```

```vue
<!-- Vue -->
<script setup>
const props = defineProps({ code:{type:String,default:"cn"}, ratio:{type:String,default:"4x3"}, size:{type:Number,default:48} });
const H = { "4x3": 0.75, "1x1": 1 };
const h = computed(() => Math.round(props.size * H[props.ratio]));
const src = computed(() => `${props.ratio}/${props.code}.svg`);
</script>
<template><img :src="src" :width="size" :height="h" :alt="code" loading="lazy" /></template>
```

### CSS Class Way (`flags.css`)

After importing `flags.css`, just use a class to attach a flag — no `<img>`, no size writing needed:

```html
<link rel="stylesheet" href="flags.css">

<i class="flag-cn"></i>          <!-- 4:3 rectangle -->
<i class="flag-cn fis"></i>      <!-- 1:1 square (add .fis) -->
<i class="flag-us" style="--fs:32px"></i>   <!-- control height via --fs, default 1em -->
```

- Rule: `.flag-<code>` is 4:3; `.flag-<code>.fis` is 1:1. The code is the file name (lowercase alpha-2, hyphenated for sub-regions).
- `flags.css` is generated by the build script — pass your domain as an argument; the domain is injected into every rule at build time (pure CSS cannot concatenate a variable into `url()`):
  ```bash
  node build.mjs https://your.cdn/               # → dist/flags.css (git-ignored, regenerated on build)
  FLAG_DOMAIN=https://your.cdn/ node build.mjs   # or use the FLAG_DOMAIN env var
  ```
- Domain is required: either as a CLI argument or via the `FLAG_DOMAIN` env var. If neither is provided, the script errors out with exit code 1.

## Region Name API · `region-name`

An edge function that takes a region code and returns the Chinese / English name. Compatible with the Cloudflare Workers style (`export async function onRequestGet({ request })`).

**Request**

```
GET /region-name?code=<code>&lang=<zh|en>
```

| Param | Description | Default |
|-------|-------------|---------|
| `code` | alpha-2 / alpha-3 / M49 three-digit numeric code, case-insensitive; supports sub-regions like `gb-eng`, `es-ct`, `sh-ac` | required |
| `lang` | `zh` (Chinese) \| `en` (English) | `en` |

**Response** (JSON, `Access-Control-Allow-Origin: *`)

```jsonc
// Hit: code is always normalized to lowercase alpha-2, ready to build a URL
{ "ok": true,  "code": "cn", "lang": "zh", "name": "中国" }

// Not found (valid format but not collected)
{ "ok": false, "code": "qqq", "lang": "en" }

// Missing parameter: HTTP 400
{ "ok": false, "error": "缺少 code 参数" }
```

**Examples**

```bash
curl "https://your-domain/region-name?code=cn&lang=zh"
# {"ok":true,"code":"cn","lang":"zh","name":"中国"}

curl "https://your-domain/region-name?code=156&lang=zh"   # M49 numeric code → China
curl "https://your-domain/region-name?code=eu&lang=zh"    # European Union
curl "https://your-domain/region-name?code=gb-eng&lang=en" # England
```

```js
// With flags: once you have the name, build the SVG path directly
const r = await fetch(`/region-name?code=${code}&lang=zh`).then(x => x.json());
if (r.ok) {
  const img = new Image();
  img.src = `4x3/${r.code}.svg`;   // r.code is already lowercase alpha-2
  label.textContent = r.name;
}
```

Key points:

- **File name is the route**: the returned `code` is always lowercase alpha-2, ready to build `4x3/<code>.svg` / `1x1/<code>.svg`.
- **Three encodings unified**: alpha-2 / alpha-3 / M49 numeric codes are all mapped to alpha-2 before lookup.
- **CORS enabled**: front-end can call cross-origin directly; `OPTIONS` preflight is allowed.
- **Use `ok` to judge a hit**: uncollected regions return 200 + `ok:false`; do not rely on the HTTP status code to distinguish.

**Deployment** (any edge runtime)

```bash
# Cloudflare Workers / Pages Functions: just place the file at functions/region-name.js
# Can also be wired as any edge function supporting the onRequestGet convention
```

> Local debug: use any Node static server + a `/region-name` proxy to forward requests to this file's `onRequestGet`.

## Deploy to Tencent EdgeOne (Fork to publish)

This project can be directly **Forked** and published with one click on [Tencent Cloud EdgeOne](https://edgeone.ai/) (edge security acceleration platform / **EdgeOne Pages**). The demo site **https://flag.doffish.com/** is deployed this way.

**1. Fork the repository**

Click **Fork** in the top right to copy the repo to your account.

**2. Create a project in EdgeOne Pages and connect the repo**

- Go to the EdgeOne console → Create project → Import Git repository, and select your forked Git repo.
- Build config:
  - **Root directory / Output directory**: `./`.
  - **Build command**: `node build.mjs https://your-domain/` (domain required; or set the `FLAG_DOMAIN` env var on the platform and use `node build.mjs`). Generates `dist/flags.css` at build time.
  - **Output directory**: `dist`.

**3. Mount the edge function `region-name`**

EdgeOne Pages' edge function convention places functions in the `edge-functions/` directory, routed by path, and supports method-level exports like `onRequestGet` (this project's `region-name.js` is exactly that style), so it works directly.

> If your EdgeOne version uses a different function directory convention (e.g. `_functions/` or `functions/`), just place `region-name.js` per the platform guide; the `onRequestGet` export signature needs no change.

```bash
# In the site root, make the route /region-name hit this edge function
mkdir -p functions
cp edge-functions/region-name.js functions/region-name.js
```

**4. Publish and bind a domain**

- After saving, EdgeOne builds automatically and assigns a `*.edgeone.app` preview domain; push / redeploy to update.
- For a custom domain (e.g. `flag.yourdomain.com`), add it under console **Domain / Binding** and configure CNAME.
- To bake your domain into `flags.css`, run the build with it: `node build.mjs https://flag.yourdomain.com/` (or set the `FLAG_DOMAIN` env var) and redeploy.

**5. Verify**

Open your site domain and confirm:
- Flag preview, ratio switch, and usage docs all work;
- Visiting `https://your-domain/region-name?code=cn&lang=zh` returns `{"ok":true,"code":"cn","lang":"zh","name":"中国"}`.
